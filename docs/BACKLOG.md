## 열린 항목

- [ ] **판독 조합의 문서 단위 재실측**: `references/image-tables.md`의 판독 조합(Upstage·Mistral·Gemini 4 Carbon·Claude 2벌)은 3쪽 9개 격자에서만 쟀다. 표 100개 규모 문서 전체에 돌려 계열별 오독 분포와 재확인 칸 비율을 잰다. 유료 호출 300회 안팎이라 실행 전 승인이 필요하다.
- [ ] **Anthropic·Azure 파서 실문서 평가**: 1.12.0에서 넣은 `anthropic_parse.py`·`azure_parse.py`는 합성 스캔 3쪽 1건으로만 확인했다. 실문서(표 많은 한국어 PDF, 스캔본, 손글씨)로 기존 파서와 견주어 SKILL.md 파서 비교표의 등급을 채우고 티어 배정 여부를 정한다. 함께 볼 것: 띠 조각을 `anthropic_parse.py`에 넣은 판독이 서브에이전트 판독과 같은 수준인지, Azure `--high-res`가 작은 글자 수치표에서 값을 하는지, Azure 단어 confidence가 손글씨 캐스케이드에서 Google Vision을 대신할 수 있는지. 유료 호출이라 문서 규모를 정한 뒤 승인을 받는다.
- [ ] **IBM 호스팅 Docling의 ODT 실호출 시험**: GitHub 이슈 #3(선택). IBM 호스팅 Docling에 공개 합성 ODT(`scripts/make_odt_fixtures.py`)를 보내 `scripts/odt_verify.py`로 원문 대조하고 결과를 `references/tier-rules.md` ODT 행에 반영한다. IBM 서비스 URL과 API 키가 필요하고 호출 비용이 들 수 있어 실행 전 승인을 받는다. 로컬 Docling은 필수 의존성으로 넣지 않는다.
- [ ] **조각 일괄 판독 실행기**: 조각마다 파서를 한 번씩 부르는 반복을 스크립트로 묶는다(병렬·재시도·실패 목록). 재실측에서 실제 병목이 확인되면 만든다.
- [ ] **달력형 학사일정 병합 표 재실측**: 1.11.0의 병합 칸 복원이 2026-08-10에 거부됐던 달력형 학사일정 2쪽(병합 79셀)에서 통과하는지, 통과한다면 값이 맞는지 확인한다. 그 문서는 이 Mac에서 찾지 못했다. 다른 달력형 학사일정 1건(6쪽 중 달력 2쪽)은 2026-11-24에 병합 범위 복원 실패와 두 엔진의 칸 불일치로 출력을 만들지 않았다.
- [ ] **점선 칸막이 검사의 남은 틈과 과검출**: (1) 칸막이 대시가 쪽 장식 무늬와 크기·행 위치가 같고 무늬 열과 가로·세로 모두 3pt 넘게 떨어져 있으면 무늬의 한 열로 묶여 재시도에서 함께 빠지고, 칸이 듬성한 표는 두 열이 합쳐진 채 통과한다(합성 PDF로만 재현). 무늬 이웃 판정에 채움 색이 같은지를 더하는 방안을 검토하되 두 엔진의 색 표현이 일치하는지부터 확인한다. (2) 세로 점선 검사가 그림 도형 글머리 기호를 칸막이로 보아 정상 표를 실패로 닫는 경우가 있다: 한 칸 안의 나란한 두 목록, 이름표 뒤의 글머리 목록, 행 높이 20pt 이하 표의 줄마다 놓인 ■ 상자(합성으로 측정, 글자로 된 글머리 기호는 해당 없음). 실문서에서 발견되면 점선이 행 경계를 넘는지 같은 조건을 검토한다. (3) 얇은 빈 행·열을 접은 표에서는 맨 위 주석(경계선에 걸친 글자)의 (행,열) 번호가 접기 전 격자 기준이라 출력된 표의 번호와 다를 수 있다(값은 주석에 함께 적힌다).
- [ ] **조각 머리글 추정 보강**: 머리글 추정이 없는 격자가 111개 중 8개 남았다. 대부분 머리글이 1단이고 높이가 본문 행과 비슷하며 첫 선 바로 아래 선이 전폭선이라 간격으로도 짧은 선 모양으로도 정하지 못하는 표다(`--header-rows pNNN.gXX=N`으로 고침). 같은 높이 선 조각을 겹쳐 세어 짧은 머리글 선이 전폭선으로 부푸는 격자가 1개 있는데, 겹친 구간을 한 번만 세면 끊긴 머리글 끝 선을 놓쳐 다른 격자에서 자료 행이 머리글에 섞이므로 회색으로 이어진 틈을 메워 재는 기준이 필요하다. 그 밖에 남은 사례: 글자가 2~3px 위에 붙은 머리글 속 짧은 선이 걸러지고, 칸을 거의 채워 세로선과의 틈이 4px 이하인 `-` 행은 경계선으로 남는다(둘 다 띠 조각의 글자 줄 누락으로는 이어지지 않는다). 행 경계선이 파선이면 칸 가운데 조각이 세로선과 이어지지 않아 묶음에서 빠지고, 세로선이 회색 235보다 옅으면 실선이어도 못 찾는다(합성으로만 재현). 2열 표와 가로선만 있는 표는 세지 못하며(63쪽 카탈로그에 실례 1개씩), 검출을 넓히면 같은 쪽의 격자 id가 밀린다. 양옆이 열린 표의 바깥 열 행 경계선과 작은 이미지 여러 장으로 쪼개진 표의 검출도 남았다.
