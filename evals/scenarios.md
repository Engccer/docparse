# docparse 전후 시험 시나리오와 채점 항목

기준 SHA a242dd9. 채점 항목은 시험을 띄우기 전에 고정했다(2026-09-27). T1~T4는 한 시험자, T5(평범한 하루)는 별도 시험자.

공통 전제(시험자에게 주는 것): macOS(zsh) 머신, `timeout`·`gtimeout` 없음, Java 있음, 필요한 API 키는 모두 설정돼 있음, 작업 폴더는 `~/Work/`. 명령은 실행하지 않는 사고 실험.

## T1. 12쪽 스캔 신청서

`~/Work/신청서_합본.pdf`: 12쪽, 텍스트 레이어 없는 스캔본. 학부모가 손으로 적은 신청서 양식이 여러 장이고, 각 장에 인원·금액 같은 숫자 칸이 있는 표가 있다. 사용자: "숫자까지 정확하게 마크다운으로 뽑아 줘." 진단 결과는 `assess_document.py`가 내는 그대로라고 가정한다. 어떤 파서를 어떤 역할로 돌리고, 무엇을 검증하고, 최종 파일 이름은 무엇인가?

채점 항목:
1. 진단 티어가 small이 아니라 medium(텍스트 레이어 없음 → 한 단계 올림)이고 추천이 llamaparse+upstage임을 안다(또는 그 차이를 짚는다).
2. 「스캔 문서 + 표에 숫자 데이터」 규칙을 적용: Upstage Primary + Mistral 교차 + LlamaParse v2 보조, 최소 3개 파서.
3. 수기 양식 표 숫자의 Primary·교차 투표에 Gemini와 LlamaParse v2를 쓰지 않는다(Upstage+Mistral만).
4. 「동일 양식 다수 합본」 규칙: 가능하면 개별 PDF로 나눠 파싱(또는 합본이면 Upstage Primary 필수·Gemini 금지·Step 5.3 강제).
5. Step 5 무결성 게이트: 산술 검증 + 셀 위치 비교(생략 불가).
6. 최종 파일 이름이 `_fused_v3_upstage+…`로 실제 반영한 파서만 나열.

## T2. 이 Mac에서 40쪽 보고서, 그림 설명 포함

`~/Work/연차보고서.pdf`: 40쪽, 텍스트 레이어 있음, 괘선 표 없음, 한국어, 본문 정보 다이어그램이 몇 개 있다. 이 Mac에서 스킬 절차대로 끝까지 진행한다. 파서 실행 명령을 실제로 어떻게 쓰고, 다이어그램 alt text는 어떻게 만들며, 산출 파일·폴더는 어떻게 남는가?

채점 항목:
1. medium: LlamaParse v2 Primary + Upstage.
2. macOS에 `timeout`이 없으므로 예시의 `timeout 300`을 그대로 쓰지 않는다(빼거나 대체).
3. 종료 코드와 출력 파일 존재를 함께 확인한 뒤 Step 4로 간다.
4. `generate_alt_text.py --map "_work-docparse/…"`의 폴더 문제를 다룬다: 개정 전(1.4.0)은 폴더가 없으면 유료 호출 뒤 실패하므로 먼저 만든다, 개정 후(1.5.0)는 스크립트가 만든다(어느 쪽이든 정답).
5. 이미지 placeholder를 단순 제거하지 않고 본문 다이어그램은 `(이미지: <alt>)`로 보존, 표지·로고는 제거.
6. Upstage 내용을 실제로 반영하면 `_fused_v3_llamaparse+upstage.md`로 rename, 개별 출력은 `_work-docparse/`로 이동.
7. Step 8 요약에 적용된 보정 규칙 절 이름과 Step 9 두 결과(추가 교차검증 필요/불필요+근거, 규칙 문서 반영 내역).

## T3. 손글씨 영어 답안 합본, 채점용

`~/Work/영어쓰기_3반.pdf`: 22쪽 스캔, 학생 1인 1쪽 손글씨 영어 작문 + 자기점검 체크박스. 채점 요소라 철자 오류를 그대로 보존해야 한다. 사용자: "채점용이니 원문 그대로. 비용은 크게 신경 안 써도 돼." 이 Mac에는 `parser-eval` 스킬이 설치돼 있지 않다. 어떤 방법·모델·도구로 전사하고 체크박스는 어떻게 판독하는가?

채점 항목:
1. 최고 충실 방법으로 Vision→Claude 비전 캐스케이드(`gvision_parse.py --raw` → 이미지+드래프트 repair)를 고른다.
2. repair 모델은 Opus(충실 최우선, 비용 무관). Sonnet은 비용 절감 때만.
3. `diff_fidelity.py`가 docparse에 없고(parser-eval 소관) 이 Mac엔 없음을 알고 대체(저신뢰 단어 표적·수동 대조 등)를 쓴다.
4. 체크박스: LlamaParse v2(최우수) 또는 `gemini_parse.py --thinking` 별도 호출. 기본 Gemini(thinking off) 금지.
5. Google Vision은 클라우드 전송이라 학생 PII 정책 확인을 거친다.
6. 오기 보존(diplomatic), 모호 글자는 판독 노트. 다페이지 시각 판독은 서브에이전트에 위임.

## T4. 크레딧 부족, 영어 비율 높은 120쪽

`~/Work/tech_manual.pdf`: 120쪽, 텍스트 레이어 있음, 영어 60%·한국어 40%의 기술 매뉴얼, 괘선 표 없음. `llamaparse_parse.py --credits`로 보니 잔여 크레딧이 1,000이다. Primary는 무엇이고 누가 교차 검증하는가? 무엇을 먼저 확인하는가?

채점 항목:
1. 120쪽 × 10크레딧 = 1,200 > 1,000이라 v2 Primary 불가를 계산한다.
2. 폴백: ODL Primary + Upstage 교차검증(「크레딧 부족 시 폴백」).
3. ODL 채택 전 본문 숫자 검증(1~2개 숫자를 Upstage와 대조, 누락이면 ODL 폐기).
4. 영어 비율 ≥50%로 Mistral Primary 고려 조건/ocr-4 폴백 후보를 언급하되 노이즈·드리프트 후처리 전제를 안다(또는 교차 투표용).
5. `--lang`은 ko가 아니라 en 계열로 줄지(혼합) 판단하고, 비한국어 조건의 정밀화(텍스트 레이어 한국어 혼합에서 Mistral은 투표용)를 안다.
6. "기본은 Upstage Primary"처럼 현재 티어 표와 다른 옛 문장을 따르지 않는다(따르면 낡은 조치 추종).

## T5. 평범한 하루: 가정통신문 DOCX (별도 시험자)

`~/Work/가정통신문_10월.docx`: 3쪽, 텍스트박스·각주·수식 없음, 표 1개. 본문에 "스레기통"이라는 오타가 하나 있다. 사용자: "이거 마크다운으로 바꿔 줘." 어떤 순서로 무엇을 하고, 최종 산출물 이름과 대화 요약은 어떻게 되는가? 어떤 파일을 읽었는지(전부/일부) 적는다.

채점 항목:
1. `assess_document.py` → docx 티어 → `docx_local_parse.py` 먼저(로컬·무료, 유료 API 호출 없음).
2. PASS면 그대로 채택: `가정통신문_10월_fused_v3_docxlocal.md`, Step 5·6(무결성 게이트·교차 검증) 생략, Step 7 최종 점검은 한다.
3. Step 0.5(편집 원본 탐색)는 PDF가 아니므로 해당 없음.
4. "스레기통"을 임의로 고치지 않는다(교정은 사용자 요청 시 `apply_corrections.py` CSV).
5. Step 8 요약: 적용 절 이름(XLSX·DOCX), Step 9 두 결과(추가 교차검증 불필요+근거, 규칙 반영 없음).
6. 읽은 파일: 이상적으로 SKILL.md(+필요 시 docx 파서 일부). tier-rules 전부를 읽지 않아도 된다.
